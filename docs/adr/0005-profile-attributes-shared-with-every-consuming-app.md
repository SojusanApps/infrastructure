# Username, email, gender, and nickname are all sent to every Consuming App by default

Keycloak's built-in `profile` and `email` client scopes — both `defaultClientScope`s on every OIDC client — carry protocol mappers for `username`, `gender`, `nickname`, and `email`/`email_verified`, so all of them are included in the ID token, access token, and UserInfo response for every Consuming App a user logs into. This surfaced while drafting the RODO/GDPR terms text: the initial draft assumed gender was collected "for internal statistics only" and that email "stays within the Service" — the token behavior contradicts both.

We considered removing gender's (and email's) mapper from the default scopes, or moving them to an optional, per-client-opt-in scope, so they'd genuinely stay internal to Sojusan Auth. We rejected this: all four attributes are actually meant to reach each Consuming App — gender and nickname for public profile display, email and username for the app's own internal account handling — so the "internal only" framing in the first draft was a mismatch between stated intent and actual, desired product behavior, not a mismatch between behavior and intent. The fix was to correct the terms/privacy text to disclose all four attributes as shared with the Consuming App the user is logged into, rather than restricting the token.
